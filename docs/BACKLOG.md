# Бэклог

Что дальше после релиза 26103102 (Ф0..Ф4 сделаны, см. `PLAN.md`). Порядок Ф5 не выбран: обсуждается
перед началом работы. Одна ветка и один PR на пункт.

## Ф5. Расширения

- **Memory mapper** 256 КБ – 1 МБ в SRAM (как в MSX1FPGA / OCM): больше RAM для MSX-DOS 2, Nextor и
  программ MSX2-класса, которые идут на MSX1 с маппером. Место в SRAM: сейчас занято до 3C0000 + 256 КБ
  (кассета) — карту памяти пересмотреть (картриджи по 1 МБ, кэш диска 768 КБ).
- **ESE-SCC MegaRAM** (SCC-картридж с RAM, загрузка образов игр Konami) и **OPLL** (MSX-MUSIC, `vm2413`
  из MSX1FPGA) — опциями OSD. Проверить место: сейчас ~60 % LUT / 84 % слайсов на Mini / Mini G.
- **Nextor на образе HDD**: `F`-слот 1 + интерфейс SD MSX1FPGA (`msxsd.vhd`) поверх эмулятора SPI
  SD-карты на `img_sdc` (CMD0/8/55/41/58/17/24/18/25, R1, токены данных) — драйвер Nextor MSX1FPGA без
  изменений. Альтернатива — прямой доступ к SD2 мимо прошивки.
- **Сохранения картриджей с батарейкой** (Game Master 2, ASCII 8 / 16 с SRAM): `.sav` через
  `kg_bk_ram` (caps bit 3, как у NES).
- **Физический дисковод** Karabas Go (`F` с флагом `physical`, как у NanoMig).
- **Turbo** и **576p50** для PAL (настоящие 50 Гц на выходе вместо 60).

## Открытые вопросы и непроверенное

- Go и Mini (26103102) на железе не проверены.
- `TAPE_IN` / `TAPE_OUT` не проверены (нет магнитофона).
- DSK-игры, Disk BASIC и CAS-игры с настоящим BIOS MSX не проверены (у пользователя нет BIOS);
  с C-BIOS проверены только тестовые картриджи `fdctest` / `tapetest`.
- Джойстики на железе не проверены, загрузка BIOS из файла — тоже.
- Симуляция: клавиатура не доходит до программы (BIOS не меняет строку матрицы, на железе работает) —
  разобраться в стенде (`keys.rom`, `SIM_KBDBG`, `SIM_ISR`).
- Защита от записи образа диска (прошивка не передаёт read-only) и смена диска во время работы
  программы — отдельно не тестировались.
- Запас по таймингу: худший путь внутри T80 (0,5–2,8 нс в зависимости от размещения); при росте ядра
  (Ф5) может понадобиться конвейеризация или `-t` другой.
- Прошивка: `core_ioctl_send` шлёт `IOCTL_STATE` 1 раньше `IOCTL_SLOT` — ядро это обходит
  (`file_reset`), но порядок можно поправить в прошивке для всех ядер.
